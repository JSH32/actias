## What a queue is

A queue is a durable message list with a handler. Sending returns
immediately; the platform delivers the message to the handler, retries
with backoff if the handler throws, and sets the message aside after
enough failures.

```lua
local mailroom = queue "mailroom"

on "queue:mailroom" (function(job)
    if job.kind == "welcome" then
        http.make_request({
            uri = "https://email.example.com/send",
            method = "POST",
            body = json.stringify({ to = job.email }),
        })
    end
end)

on "fetch" (function(request)
    mailroom:send({ kind = "welcome", email = "ada@example.com" })
    return { status_code = 202, body = "queued" }
end)
```

The handler is declared with `on "queue:<name>"` matching the queue's
name.

## Guarantees

**At-least-once delivery.** A handler that throws gets the message
again after a delay, then a longer delay. Write handlers that are safe
to run twice on the same message: check an id, or use statements like
`INSERT OR IGNORE` and `UPDATE ... WHERE state = 'pending'`.

**One message, one handler run.** Queues distribute work, they do not
broadcast. Ten workers draining a thousand messages produce a thousand
handler runs.

**Bounded retries.** After enough failed attempts a message moves to
the dead-letter list. It stops retrying, does not block the queue, and
stays there until you look at it. The console lists dead letters and
can requeue them.

## What belongs in a queue

Email, push notifications, webhooks, thumbnail fetches, anything where
a minute of delay is acceptable and the request path should not wait.

## What does not

**Addressed work.** "Tell this account it was outbid" is a call to
that object, not a queue message. Queues are for work no specific
entity owns.

**Multi-step processes.** If the job waits on a human or has stages,
use a [workflow](/docs/runtime/workflows). The test: if anyone will
ask "how is that specific job doing", it needs a workflow, because
queue messages are anonymous.

## Inspecting

The console shows depth, in-flight count, the delivery journal, dead
letters, and a retry action.
