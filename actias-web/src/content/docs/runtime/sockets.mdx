## Upgrading

A websocket handshake arrives as an HTTP request, so it authenticates
in the same router as everything else.

```lua
on "fetch" (function(request)
    if request.upgrade and request.path == "/ws" then
        local user = authed(request)
        if user == nil then
            return { status_code = 401, body = "log in first" }
        end

        return request:upgrade(function(sock)
            sock:follow(Room("lobby"), "message")
            sock:each(function(item)
                if item.kind == "event" then
                    sock:send({
                        event = "message",
                        text = item.event.data.text,
                    })
                end
            end)
        end, User(user))
    end

    -- ordinary routes
end)
```

`request.upgrade` is present only when the request is a real
handshake. `request:upgrade(program, identity)` takes the connection
program and the identity the connection speaks as.

The request environment does not die at the response. It becomes the
connection's environment and lives as long as the connection, so the
program is a closure over whatever the handler already computed.

## Identity

The second argument is an object handle: `User(name)`,
`Account(name)`. The connection speaks as that identity, and every
[stream gate](/docs/runtime/streams) sees it in the same shape an
object follower has.

Mint it after authenticating. It is fixed for the life of the
connection and cannot be changed by anything the client sends.

## The loop

`sock:each(handler)` runs the handler for each item until the
connection closes. Returning `true` stops the loop.

Items are one of two kinds:

```lua
sock:each(function(item)
    if item.kind == "event" then
        -- a delivered stream event: item.event.topic, .from, .data
    elseif item.kind == "frame" then
        -- a json frame the client sent: item.data
    end
end)
```

Both arrive on the same inbox, so there is no select machinery.
`sock:recv()` is the same source as a single awaited item if you want
to write the loop yourself.

## Sending

`sock:send(value)` writes one JSON frame. There is no platform wire
protocol: the frames on the wire are the ones your program sends. If
you want clients to change subscriptions, define a frame for it and
handle it in the loop:

```lua
sock:each(function(item)
    if item.kind == "frame" and item.data.op == "watch" then
        if watching then sock:unfollow(Auction(watching), "bid") end
        watching = item.data.id
        sock:follow(Auction(watching), "bid")
    end
end)
```

Follow targets are handles named in your code, never strings taken
from the wire.

## Connection edges

`sock:follow` makes an edge like `state:follow` does, with different
promises:

| | object edge | connection edge |
|---|---|---|
| delivery | at-least-once | at-most-once |
| retry | yes, with backoff | none |
| on failure | retried, then dropped | edge removed |
| lifetime | until unfollowed | dies with the connection |

A tab that closes takes its edges with it. Nothing accumulates for
dead connections.

Put durability one hop back. The account object follows what must not
be missed; the connection follows the account for live updates. On
reconnect the client reads the object's state and continues.

## Backpressure and limits

Each connection has a bounded inbox. A program that stops consuming
fills it, and the connection closes rather than buffering without
limit.

Returning from the program, throwing, or the peer disconnecting all
end the connection and remove the edges it made.
