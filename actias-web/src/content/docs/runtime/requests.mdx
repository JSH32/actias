title: How a request runs
lead: Each request builds a fresh Lua environment, runs your handler, and discards it.

## One environment per request

Nothing survives in memory between requests.

```lua
local seen = 0

on "fetch" (function(request)
    seen = seen + 1
    return { body = tostring(seen) }   -- always "1"
end)
```

Each request gets its own copy of the script's state. Nothing is
shared between requests, and nothing needs cleaning up after one
finishes.

Compiled code is shared; only the mutable environment is per-request,
so building one is cheap.

Anything you need to keep goes in [kv](/docs/reference/kv), a
[database](/docs/reference/database), or an
[object](/docs/runtime/objects).

## The top level runs once

Code outside your handler runs when the environment is built. That is
where declarations go:

```lua
local visits = kv "visits"
local db = database "catalog" { migrations = "migrations/catalog" }

on "fetch" (function(request)
    -- handler body
end)
```

Declarations are only valid at the top level. To collect them the
platform runs your entry point with every effectful surface stubbed
out, so it derives the contract without executing a single handler.

## Request and response

The handler takes a request table and returns a response table.

```lua
on "fetch" (function(request)
    if request.method == "POST" and request.path == "/api/echo" then
        return {
            status_code = 200,
            headers = { ["content-type"] = "application/json" },
            body = request.body,
        }
    end
    return { status_code = 404, body = "no such route" }
end)
```

`request.path` is relative to your script: one served at `/hello/`
sees `/api/echo`, not `/hello/api/echo`. `request.query` is a decoded
table. Every field is in the [http reference](/docs/reference/http).

## Budget

A request is bounded by work, not by time: waiting on io costs nothing,
computing costs. The ceiling is about a second of solid computation,
which no ordinary handler comes near.

Work that does not fit belongs in a [queue](/docs/runtime/queues) or a
[workflow](/docs/runtime/workflows).

### Gotchas

- Top-level state looks like a cache and is not one. The counter above
  resets on every request, including in production.
- Work at the top level is paid on every request, since the
  environment is rebuilt each time. Put it in the handler.
- `kv "visits"` inside a handler is an error, not a late declaration.
  The declaration forms are top level only.
