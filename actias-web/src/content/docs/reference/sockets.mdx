## Declare a class

```lua
local Session = connection "Session" {
    open = function(conn) end,
    frame = function(conn, data) end,
    event = function(conn, event) end,
    timer = { every = "30s", run = function(conn, missed) end },
    close = function(conn) end,
}
```

Each handler is optional; a key outside these five refuses at
declaration. Nothing calls a connection, so there are no methods:
handlers run when the wire, an edge or the timer delivers.

<table>
  <thead>
    <tr><th>Handler</th><th>Runs</th></tr>
  </thead>
  <tbody>
    <tr><td><code>open(conn)</code></td><td>once, before any item; the follow calls usually live here</td></tr>
    <tr><td><code>frame(conn, data)</code></td><td>per JSON text frame the client sent; binary and non-JSON frames are dropped</td></tr>
    <tr><td><code>event(conn, event)</code></td><td>per delivered edge event; takes a policy instead of a function (below)</td></tr>
    <tr><td><code>timer.run(conn, missed)</code></td><td>every <code>timer.every</code>, one second or more; <code>missed</code> counts ticks that fell during a previous run</td></tr>
    <tr><td><code>close(conn)</code></td><td>after the wire ends, either side; edges sever after it returns</td></tr>
  </tbody>
</table>

Handlers for one connection run one at a time, in arrival order, each
under the per-call budget. A tick is never queued behind the inbox,
and a connection with a timer never hibernates.

## The forward policy

`event` takes a policy in place of a function, the same hook-or-policy
shape `publishes` uses for topics:

```lua
local Account = objects "Account"

local Feed = connection "Feed" {
    open = function(conn) conn:follow(Account(conn.name), "events") end,
    event = "forward",
}
```

Each delivery then reaches the client as

```json
{ "type": "event", "topic": "...",
  "from": { "id": "...", "class": "...", "name": "..." },
  "data": { } }
```

built by the platform, with no vm involved, so a hibernated connection
stays hibernated while it relays. Declare a function instead to choose
your own wire shape, and pay a handler call per event for it.

Declaring neither drops deliveries, which is what you want only when
the follow exists to be counted (`state:followers`) rather than heard.

## Upgrading

```lua
if request.upgrade and request.path == "/ws" then
    return request:upgrade(Session, { room = "lobby" }, User(name))
end
```

`request:upgrade(Class, seed?, identity)` returns the value your
fetch handler should return. The seed becomes the initial
`conn.state`; the identity is an object handle the connection speaks
as for the rest of its life. Two arguments means no seed.

<table>
  <thead>
    <tr><th>Refused</th><th>Text</th></tr>
  </thead>
  <tbody>
    <tr><td>a class that is not a declared connection</td><td><code>upgrade takes a declared connection class</code></td></tr>
    <tr><td>a connection declared in another script</td><td><code>Connection 'X' is not declared in this script.</code></td></tr>
    <tr><td>an identity that is not an object handle</td><td>refused; a platform class refuses with <code>a connection cannot speak as a platform class.</code></td></tr>
    <tr><td>a seed over 64 KB serialized</td><td>refused at upgrade</td></tr>
    <tr><td>a second upgrade in one request</td><td><code>one upgrade per request.</code></td></tr>
  </tbody>
</table>

## conn

<table>
  <thead>
    <tr><th>Field</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td><code>conn.state</code></td><td>json-serializable session table, seeded at upgrade, kept across handlers; past 64 KB the handler raises and the connection ends</td></tr>
    <tr><td><code>conn.name</code></td><td>the identity's instance name</td></tr>
    <tr><td><code>conn.class</code></td><td>the identity's class</td></tr>
    <tr><td><code>conn:send(value)</code></td><td>writes one JSON text frame</td></tr>
    <tr><td><code>conn:follow(target, topic, filter?)</code></td><td>makes a connection edge; returns true</td></tr>
    <tr><td><code>conn:unfollow(target, topic)</code></td><td>removes it</td></tr>
    <tr><td><code>conn:close()</code></td><td>ends the connection</td></tr>
    <tr><td><code>conn.closed</code></td><td>on the <code>close</code> handler only: <code>{'{ by, reason? }'}</code>, where <code>by</code> is <code>peer</code>, <code>program</code>, <code>error</code> or <code>overflow</code></td></tr>
  </tbody>
</table>

The event a handler receives is shaped
`{ topic = "...", from = { id, class, name }, data = {...} }`.

## Opening a wire outward

The same class dials as well as accepts:

```lua
local name = Upstream:open("wss://api.example/realtime", { room = "lobby" }, {
    headers = { Authorization = "Bearer " .. key },
    protocols = { "json" },
})
```

<table>
  <thead>
    <tr><th>Argument</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td><code>url</code></td><td><code>ws://</code> or <code>wss://</code>; the egress policy applies, and every address the host resolves to is checked before any is dialled</td></tr>
    <tr><td><code>seed</code></td><td>the initial <code>conn.state</code>, optional, 64 KB cap</td></tr>
    <tr><td><code>options.headers</code></td><td>request headers for the handshake</td></tr>
    <tr><td><code>options.protocols</code></td><td>the subprotocol list</td></tr>
    <tr><td>returns</td><td>the instance name, once the handshake is up; the call raises with the reason otherwise, and gives up after 10 s</td></tr>
  </tbody>
</table>

The connection speaks as its own class and the minted name, lives on
the node that opened it, and is listed in the console's Connections
page beside the inbound ones. There is no socket handle: to send up
the wire, publish on a topic the connection follows, and send the
payload from its `event` handler. See [wires this project
opened](/docs/runtime/sockets#wires-this-project-opened) for the
pattern and who should own the reopen.

## Example

```lua
local Account = objects "Account"
local Auction = objects "Auction"

local Feed = connection "Feed" {
    open = function(conn)
        conn:follow(Account(conn.name), "events")
    end,

    -- The platform envelope, without waking this program.
    event = "forward",

    frame = function(conn, data)
        if data.op == "watch" then
            if conn.state.watching then
                conn:unfollow(Auction(conn.state.watching), "bid")
            end
            conn.state.watching = data.id
            conn:follow(Auction(data.id), "bid")
        end
    end,
}

on "fetch" (function(request)
    if request.upgrade and request.query.user then
        return request:upgrade(Feed, nil, Account(request.query.user))
    end
    return { status_code = 404, body = "" }
end)
```

### Gotchas

- Locals in the fetch handler do not reach the handlers; a session's
  context travels through the seed into `conn.state`.
- `conn.state` dies with the connection on purpose. Anything that must
  survive belongs on an object one hop back.
- Connection edges are at-most-once and die with the connection.
- The inbox holds 256 items. Deliveries that overflow it sever every
  edge the connection holds and leave the socket open; client frames
  that overflow it close the wire.
- The only frame the platform defines is the forwarded event envelope
  above, and declaring an `event` handler replaces it. Every other
  frame on the wire is one your handlers send or interpret, so follow
  targets come from your code, never from a string the client sent.
