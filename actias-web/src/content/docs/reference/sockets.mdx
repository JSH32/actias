## Upgrading

```lua
if request.upgrade and request.path == "/ws" then
    return request:upgrade(function(sock)
        -- connection program
    end, User(name))
end
```

`request:upgrade(program, identity)` returns the value your fetch
handler should return. The identity is an object handle; the
connection speaks as it for the rest of its life.

## Methods

<table>
  <thead>
    <tr><th>Method</th><th>Does</th></tr>
  </thead>
  <tbody>
    <tr><td><code>each(handler)</code></td><td>runs the handler per item until close; return true to stop</td></tr>
    <tr><td><code>recv()</code></td><td>one item, or nil once closed</td></tr>
    <tr><td><code>send(value)</code></td><td>writes one json frame</td></tr>
    <tr><td><code>follow(target, topic, filter?)</code></td><td>makes a connection edge</td></tr>
    <tr><td><code>unfollow(target, topic)</code></td><td>removes it</td></tr>
    <tr><td><code>close()</code></td><td>ends the connection</td></tr>
  </tbody>
</table>

## Items

`each` and `recv` yield items of two kinds:

```lua
-- a delivered stream event
{ kind = "event", event = { topic = "...", from = { id, class, name }, data = {...} } }

-- a json frame from the client
{ kind = "frame", data = {...} }
```

Both arrive on the same inbox.

## Example

```lua
return request:upgrade(function(sock)
    sock:follow(Account(user), "events")
    local watching = nil

    sock:each(function(item)
        if item.kind == "event" then
            sock:send({ topic = item.event.topic, data = item.event.data })
        elseif item.kind == "frame" and item.data.op == "watch" then
            if watching then sock:unfollow(Auction(watching), "bid") end
            watching = item.data.id
            sock:follow(Auction(watching), "bid")
        end
    end)
end, Account(user))
```

### Gotchas

- Iterate with `each`, not a generic for. Luau cannot resume a yield
  inside an iterator, so `for item in sock:each()` fails at runtime.
- Connection edges are at-most-once and die with the connection.
  Anything that must survive belongs on an object one hop back.
- The inbox holds 256 items. A program that stops consuming closes the
  connection rather than buffering.
- There is no platform wire protocol. The frames on the wire are the
  ones your program sends and interprets, so follow targets come from
  your code, never from a string the client sent.
