## Declaring

```lua
local db = database "catalog"
```

Top level only, scoped to the project.

## Methods

```lua
db:exec(sql, params?)       -- write; returns rows affected
db:query(sql, params?)      -- rows
db:query_one(sql, params?)  -- first row, or nil
db:read(sql, params?)       -- rows, read path
db:read_one(sql, params?)   -- first row, or nil
db:batch(statements)        -- several statements together
```

`read` and `read_one` are reads that can be served from the nearest
copy. Use them for queries; use `query` when you need to read your own
uncommitted writes inside the same call.

Parameters are bound, never interpolated:

```lua
db:exec("INSERT INTO listings (id, title) VALUES (?, ?)", { id, title })
local row = db:read_one("SELECT * FROM listings WHERE id = ?", { id })
```

## Migrations

Schema lives in SQL files in the bundle, under
`migrations/<database-name>/`:

```
migrations/catalog/0001_listings.sql
migrations/catalog/0002_sales.sql
```

Create them with the CLI, then fill in the SQL:

```sh
actias sql catalog create listings
```

Files apply in filename order, at the first call that touches the
database, inside that call's transaction. A failed migration applies
nothing and surfaces as that call's error.

Adding `0003_*.sql` and publishing upgrades the schema on the next
touch. Nothing runs migrations at publish time.

## Example

```lua
local db = database "catalog"

on "fetch" (function(request)
    db:exec("INSERT INTO visits (at) VALUES (?)", { os.time() })
    local total = db:read_one("SELECT COUNT(*) AS n FROM visits").n
    return { body = json.stringify({ visits = total }) }
end)
```
