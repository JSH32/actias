## Declare

```lua
local mailroom = queue "mailroom"

on "queue:mailroom" (function(job)
    -- job is whatever was sent
end)
```

Top level only. The handler name must match the queue name exactly.

## Methods

<table>
  <thead>
    <tr><th>Method</th><th>Returns</th></tr>
  </thead>
  <tbody>
    <tr><td><code>send(payload)</code></td><td>true, as soon as the message is durable</td></tr>
    <tr><td><code>stats()</code></td><td><code>depth</code>, <code>in_flight</code>, <code>oldest_pending</code>, <code>dead_letters</code></td></tr>
  </tbody>
</table>

`depth` counts everything still queued, in-flight messages included.
The payload must be JSON-representable, since a message can cross
machines.

## Delivery

<table>
  <thead>
    <tr><th>Promise</th><th>What your handler must do</th></tr>
  </thead>
  <tbody>
    <tr><td>at-least-once</td><td>tolerate running twice on one message</td></tr>
    <tr><td>one message, one run</td><td>nothing; queues distribute, they do not broadcast</td></tr>
    <tr><td>5 attempts, then dead-lettered</td><td>throw when the input can never work</td></tr>
  </tbody>
</table>

The first retry waits 2 seconds and each further one doubles, capped
at an hour. A dead letter stops retrying, does not block the queue, and
waits in the console until you requeue or drop it.

## Example

```lua
local mailroom = queue "mailroom"

on "queue:mailroom" (function(job)
    if job.kind == "thumbnail" then
        local response = http.make_request({ uri = job.url, method = "GET" })
        db:exec("UPDATE listings SET preview = ? WHERE id = ?",
            { response.status_code == 200 and "ok" or "unavailable", job.id })
    end
end)

on "fetch" (function(request)
    mailroom:send({ kind = "thumbnail", id = "lot-1", url = "https://..." })
    return { status_code = 202, body = "queued" }
end)
```

### Gotchas

- Throwing is how you dead-letter deliberately. A job whose input can
  never work should throw rather than silently succeed.
- `send` returns before the handler runs, so a handler failure never
  surfaces at the call site. The console is where you see it.
- A queue with no matching handler accepts sends and never delivers
  them. Nothing warns you, so check the name.
