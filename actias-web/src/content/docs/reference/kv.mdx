## Declare

```lua
local visits = kv "visits"
```

Top level only. Scoped to the project, so two scripts in one project
declaring `kv "visits"` share it.

## Methods

```lua
ns:get("hits")                          -- value, or nil
ns:set("hits", 41)
ns:set_batch({ hits = 41, banner = { text = "back at 09:00" } })
ns:delete("hits")
ns:list({ limit = 100 })                -- one page, ascending by key
```

  <thead>
    <tr><th>Method</th><th>Returns</th></tr>
  </thead>
  <tbody>
    <tr><td><code>get(key)</code></td><td>the value, or nil</td></tr>
    <tr><td><code>set(key, value)</code></td><td>nothing</td></tr>
    <tr><td><code>set_batch(table)</code></td><td>nothing; writes every pair, deletes the nil ones</td></tr>
    <tr><td><code>delete(...keys)</code></td><td>nothing</td></tr>
    <tr><td><code>list(options?)</code></td><td>one page: <code>{'{ entries, cursor }'}</code></td></tr>
  </tbody>

## Listing

One page per call, in ascending key order. `entries` is an array of
`{ key, value }`; `cursor` names where the next page starts, and a
page without one is the last. `limit` defaults to 100, capped at 1000.

```lua
local cursor
repeat
    local page = ns:list({ cursor = cursor })
    for _, entry in page.entries do
        print(entry.key, entry.value)
    end
    cursor = page.cursor
until not cursor
```

A page is a snapshot of a range, not a lock: writes that land between
pages appear or not depending on where their keys sort.

## Types

kv stores the type you wrote and returns it.

<table>
  <thead>
    <tr><th>You write</th><th>You get back</th></tr>

    <tr><td>string</td><td>string</td></tr>
    <tr><td>integer</td><td>integer</td></tr>

  </tbody>
</table>

## Example

```lua
local cache = kv "cache"

on "fetch" (function(request)
    local hits = (cache:get("hits") or 0) + 1
    cache:set("hits", hits)
    return { body = tostring(hits) }
end)
```

### Gotchas

- Listing pages by key order; there is no query by value. Anything
  richer than a key range wants a [database](/docs/reference/database).
- Functions and userdata cannot be stored. Tables go through JSON, so
  what comes back is a copy, not the table you put in.
- A nil value in `set_batch` is a delete, not a stored nil.
